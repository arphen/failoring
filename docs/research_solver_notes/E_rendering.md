# Rendering of fabric and digital humans for a garment design app (Godot 4.3 Forward+ real-time plus offline "render mode"; CLO-level stills on Apple Silicon)

Scope note: about 30 tool calls; many fetched pages were summarised by a small model, so exact figures are quoted only as the fetch returned them. Anything with no located source is in Inferences or Gaps. Effort estimates (S/M/L/XL) and Apple/Metal suitability judgements are my inferences, not sourced. Dates: the Mitsuba and Dr.Jit Metal items post-date my training data and come only from the docs pages cited.

## Q1. Cloth appearance models: what exists, what it costs, what addresses which failure

### Takeaway
Two tiers exist. (a) Cheap analytic shaders (Charlie/velvet sheen, Filament cloth, Godot built-ins, microcylinder/Irawan-style anisotropy) run in a rasteriser and fix the "plastic/tarp" look. (b) Yarn/ply/fibre-level micro-appearance models (Zhao, Khungurn, Montazeri, Khattar, Wu & Yuksel) give true weave/knit/fuzz/translucency but are offline, or realtime only with fibre-geometry tricks. Most of tier (b) has no public code (or no stated licence), so for a small team the realistic path is tier (a) live plus baked weave textures, and a path-traced offline mode using Cycles/Mitsuba with procedural fabric geometry or a ply-level approximation.

### Cited Findings
- Irawan & Marschner, "Specular Reflection from Woven Cloth", ACM TOG 31(1), 2012, DOI 10.1145/2077341.2077352. Procedural scattering model from fibre specular reflection with a few physical parameters (fibre, yarn geometry, weave pattern), needs no image data; validated against measurements and BTFs of two fabrics. Code release not stated on the author page. — [Author page](https://www.cs.cornell.edu/~srm/publications/TOG12-cloth.html)
- Sadeghi, Bisker, De Deken, Jensen, "A Practical Microcylinder Appearance Model for Cloth Rendering", ACM TOG 2013 (venue year header blank in the PDF I read; SIGGRAPH 2013 per the discmaster path). Threads as microcylinders in two orthogonal directions, tangents from mesh UV gradients; parameters fitted by eye or macro photo; Irawan-Marschner is described by the authors as needing costly numerical integration and fitting. Cost: CPU ray tracer 512x512 at 144 spp about 51 min (2.83 GHz Core 2); GPU shader about 100 ms/frame at 1 spp, single directional light, on a mobile GT420 laptop (2013 hardware, so far cheaper today). Limitations stated: no accurate close-ups, no masking between orthogonal threads, no multiple scattering between threads, transmission term unexplored, distant viewing only. — [PDF](https://datarepo.eng.ucsd.edu/visiondata/obisker/public_html/cloth/microcylinder-sg13.pdf)
- Zhao, Jakob, Marschner, Bala, "Structure-aware Synthesis for Predictive Woven Fabric Appearance", TOG (SIGGRAPH) 2012: project page lists a "Code and Data" directory; licence not stated. — [Cornell cloth project](https://research.cs.cornell.edu/ctcloth)
- Zhao, Luan, Bala, "Fitting Procedural Yarn Models for Realistic Cloth Rendering", TOG 35(4) (SIGGRAPH 2016): paper plus code-and-data zip (131.6 MB) listed; licence not stated; no render time reported on the page. — [Cornell cloth project](https://research.cs.cornell.edu/ctcloth)
- Khungurn, Schroeder, Zhao, Marschner, Bala, "Matching Micro-Appearance Models to Real Fabrics", TOG 35(1), Dec 2015 (DOI 10.1145/2818648). No code listed. Prompt called it "Matching real fabrics with micro-appearance models"; the project page uses the title given here. — [Cornell cloth project](https://research.cs.cornell.edu/ctcloth); [DOI](https://www.doi.org/10.1145/2818648)
- Khungurn, Wu, Noeckel, Marschner, Bala, "Fast Rendering of Fabric Micro-Appearance Models Under Directional and Spherical Gaussian Lights", SIGGRAPH Asia 2017: micro-appearance rendering "can take hours per frame"; method renders supersampled images in tens of seconds on a commodity GPU vs tens of minutes on a compute cluster for path tracing. No code listed. — [Cornell cloth project](https://research.cs.cornell.edu/ctcloth)
- Luan, Zhao, Bala, "Fiber-Level On-the-Fly Procedural Textiles", CGF/EGSR 2017: claims 60-200x less memory than existing methods; no code. — [Cornell cloth project](https://research.cs.cornell.edu/ctcloth)
- Wu & Yuksel, "Real-time Fiber-level Cloth Rendering", I3D 2017 (also TVCG version "Real-time Cloth Rendering with Fiber-level Detail"). Procedural fibre generation from yarn control points, LOD, yarn-level AO, self-shadow with low-res shadow maps; "real-time frame rates" for knitwear with over 100M fibre curves; no GPU or fps named; no code repository, yarn-level model data linked. — [Project page](https://people.csail.mit.edu/kuiwu/rtfr.html)
- Montazeri, Gammelmark, Zhao, Jensen, "A Practical Ply-Based Appearance Model of Woven Fabric", TOG 39(6), SIGGRAPH Asia 2020. Ply-level structure with local fibre simulation, handles reflection and transmission, "light-weight and scales to large pieces of clothing"; no benchmarks or code on the page. Authors from Luxion (KeyShot maker). — [Author page](https://cseweb.ucsd.edu/~henrik/papers/practical_ply_based_cloth_appearance/)
- Khattar, Zhu, Padovani, Aurby, Droske, Yan, Montazeri, "A Multi-scale Yarn Appearance Model with Fiber Details", arXiv:2401.12724 (Jan 2024, v2 Mar 2025): traces only yarn curves, ply/fibre shapes implicit with a shadowing term; 3-5x faster than prior methods in near-field, 20% faster in distance via multi-scale; no code mentioned. This is the closest match to the "LOD for yarns" item in the prompt (the prompt's "Zhu 2023" fur LOD paper is Zhu, Zhao, Wang, Xu, Yan, "Practical Level-of-Detail Aggregation of Fur Appearance", located but not read). — [arXiv](https://arxiv.org/abs/2401.12724); [Fur aggregation PDF](https://sites.cs.ucsb.edu/~lingqi/publications/paper_fur_aggregation.pdf)
- A 2026 SIGGRAPH Asia paper "Curvature-Aware Multi-Scale Gaussian Appearance Model for Fabric" (Khattar et al., fabric flyaways) exists per search results; the PDF fetch failed, so nothing beyond the title is verified. — [PDF link (unread)](https://graphics.unizar.es/projects/Khattar2026FabricFlyaways/Curvature-Aware_Multi-Scale_Gaussian_Appearance_Model_for_Fabric_files/fabric_flyaways_SIGAsia2026.pdf)
- Practical Ply-Based Appearance Modeling for Knitted Fabrics (EGSR/SR 2021, DOI 10.2312/SR.20211297) located by search, not read. — [EG DL](https://diglib.eg.org/items/a1344b2c-142b-47ff-8f59-00d51d4ebce7/full)
- Estevez & Kulla (Sony Pictures Imageworks), "Production Friendly Microfacet Sheen BRDF", SIGGRAPH 2017 Physically Based Shading course: exponentiated-sinusoid NDF (the "Charlie" distribution), cheap to compute, fitted shadowing term (no LUT), layering via albedo scaling with LUT, min-albedo scaling loses some energy, non-reciprocal terminator softening; uniform hemisphere sampling worked better than inverse-CDF. — [Course PDF](https://blog.selfshadow.com/publications/s2017-shading-course/imageworks/s2017_pbs_imageworks_sheen.pdf)
- Filament cloth model: uses Charlie NDF D=(2+1/alpha) sin^(1/alpha) theta/(2 pi), with the Neubelt visibility term instead of the Estevez shadowing for cost; velvet NDF normalised by Neubelt & Pettineo (Ready At Dawn, 2013) from Ashikhmin & Premoze (2007); sheenColor + subsurfaceColor parameters, no metallic/reflectance; wrapped-diffuse subsurface with w=0.5; thin translucent layers only covered as clear coat, the subsurface section is [TODO] in the doc. — [Filament docs](https://google.github.io/filament/Filament.md.html)
- Zeltner et al. (NVIDIA), "Real-Time Neural Appearance Models", 2023, arXiv:2305.02678. Latent textures + small MLP decoding BRDF; up to 10x faster than moderately optimised non-neural layered shading; training about 4-5 h per material on one RTX 4090; per-material training, no editability, FP16 inference; code release not confirmed by the page I read. Neural nets are unsuitable for user-chosen fabrics editable in-app. — [ar5iv](https://ar5iv.labs.arxiv.org/html/2305.02678); [NVIDIA page](https://research.nvidia.com/labs/rtr/neural_appearance_models/assets/nvidia_neural_materials_author_paper.pdf)
- Godot 4.3 spatial shader built-ins relevant to cloth: render modes diffuse_burley (default), diffuse_lambert_wrap, diffuse_toon; specular_schlick_ggx (default), specular_toon, specular_disabled; fragment outputs SSS_STRENGTH, SSS_TRANSMITTANCE_COLOR/DEPTH/BOOST, BACKLIGHT, RIM, RIM_TINT, CLEARCOAT, ANISOTROPY, ANISOTROPY_FLOW; custom light() runs per light per pixel with DIFFUSE_LIGHT/SPECULAR_LIGHT += (and is skipped for unshaded/vertex_lighting). No dedicated sheen output is listed in what I retrieved. — [Godot docs (es mirror of 4.3 source)](https://docs.godotengine.org/es/4.3/_sources/tutorials/shaders/shader_reference/spatial_shader.rst.txt)
- Godot transparency limits: transparent materials cannot cast shadows, are absent from hint_screen_texture/hint_depth_texture, thus excluded from SSR and refraction; SDFGI sharp reflections do not show on transparent materials; sorting issues. This directly constrains chiffon/organza as alpha-blended surfaces. — same Godot doc

### Inferences
Ranked list (rank = value per effort for this product; cost/quality as cited above; effort and Apple notes are my judgement). "Fails" refers to product failure 1 = fabric appearance (microstructure, sheen, fuzz, thickness, translucency), 2 = real-time vs offline gap, 3 = uncanny body/face.
1. Charlie/Estevez sheen + Filament-style cloth in a Godot custom light() or fragment shader (Estevez & Kulla 2017; Filament, Apache-2.0 per project but licence not verified in this session). Fails 1 (sheen/velvet look). Real-time yes; Metal-agnostic (just shaders). Effort S. Risk: Godot lacks a built-in sheen lobe so energy compensation and IBL must be hand-rolled; no sheen in SDFGI/reflection probes.
2. Baked weave data: normal + height + per-yarn tangent/ID maps generated procedurally from weave notation, with anisotropic highlight along yarn tangent via ANISOTROPY/ANISOTROPY_FLOW or microcylinder-style lobes (Sadeghi 2013, Irawan & Marschner 2012). Fails 1 (microstructure, anisotropic colour shifts). Real-time yes (Sadeghi 100 ms on 2013 mobile GPU). Effort M. Risk: Sadeghi model does not handle close-ups or multiple scattering; Irawan needs numerical integration/fitting.
3. Fuzz shell / alpha-cutout fibre cards or shell layers plus rim/BACKLIGHT for flyaways on brushed/knit fabrics (inferred, no specific source; Wu & Yuksel show full fibre geometry is possible but without code). Fails 1 (fuzz). Real-time yes. Effort M. Risk: transparency sorting limits in Godot.
4. Offline render mode in a path tracer (Cycles Metal-RT, or Mitsuba 3 Metal) with displaced weave geometry or textured BSDF + thin-sheet transmission; see Q3. Fails 2 (gap between preview and still). Effort M. Risk: duplicating materials in two renderers; need a material-export layer.
5. Ply-level appearance model (Montazeri 2020) or multi-scale yarn model (Khattar 2024) re-implemented in an offline renderer. Fails 1 (translucency, thickness, true weave). Offline only. Effort XL (no public code found, Mitsuba-style plugin, then fitting). Risk: re-implementation from papers; licences unknown.
6. Zhao 2016 procedural yarn fitting: code+data exist, licence unstated. Fails 1 (matching real fabrics from CT/photos). Offline; needs volumetric rendering. Effort L-XL. Risk: licence ambiguity, research code.
7. Wu & Yuksel real-time fibre-level rendering. Fails 1 and 2 (fuzz + real time at close range). Effort XL in Godot (needs compute/geometry generation; Godot 4.3 has no mesh shaders; unverified). Risk: no code.
8. Neural appearance models (Zeltner 2023). Fails 1 in principle. Effort XL, per-material training needing RTX-class GPU; Apple suitability poor (inference via Metal cooperative vectors exists in Dr.Jit per its changelog but training stack is CUDA-centric; inference). Not recommended for user-editable fabrics.
Translucent chiffon: nothing in located sources gives a ready recipe. Inference: use two-sided diffuse transmission/thin-sheet BSDF offline (Cycles has a translucent/thin options; not verified here) and in Godot use ALPHA plus BACKLIGHT, accepting no refraction/shadow-cast and sorting artefacts per the Godot docs above.

## Q2. Real-time techniques in a rasteriser vs a path tracer; Godot 4.3 limits; alternatives

### Takeaway
Godot 4.3 can host a custom sheen/anisotropy cloth shader and offers SSS and backlight fields, but transparency handling (no shadows, no SSR/refraction participation, sorting) is a real limit for thin sheer fabrics. Godot 4.4 added a native Metal driver for Apple Silicon (Intel Macs stay on MoltenVK), so the Apple-side backend is OK. Filament has a documented cloth model and is a viable standalone preview alternative; bgfx was not researched.

### Cited Findings
- Godot 4.4 dev snapshot 1: Metal rendering backend, "only support Metal on Apple Silicon (ARM) devices" (iOS, M1/M2/M3 Macs); Intel Macs continue on MoltenVK; "Early results show that the Metal backend on macOS is at least as fast as the Vulkan backend." The page does not state which renderers (Forward+/Mobile) run on it. — [Godot 4.4 dev 1](https://godotengine.org/article/dev-snapshot-godot-4-4-dev-1/)
- Metal driver anecdote: shader compile via GLSL to SPIR-V to MSL to PSOs at runtime; one user reports a blocking first-launch freeze of about 5 s on iPhone with the Mobile renderer; unverified, single-device, user-reported; Apple DTS suggests async pipeline creation and MTLBinaryArchive. — [Apple Developer Forums](https://developer.apple.com/forums/thread/824902)
- Godot spatial shader and transparency limits as listed in Q1 — [Godot docs](https://docs.godotengine.org/es/4.3/_sources/tutorials/shaders/shader_reference/spatial_shader.rst.txt)
- Filament cloth model is a rasteriser-oriented implementation (see Q1) — [Filament docs](https://google.github.io/filament/Filament.md.html)
- Real-time neural shading can run in fragment shaders and ray tracing (NVIDIA, 2023) — [ar5iv](https://ar5iv.labs.arxiv.org/html/2305.02678)

### Inferences
- Plan: keep Godot as the interactive previewer with items 1-3 of the ranked list; treat anything needing refraction, inter-yarn scattering or soft transmitted shadows as offline-only.
- For chiffon in the previewer, consider rendering sheer layers in a custom ordered pass or depth-peeled approximation (unverified), because Godot transparent materials do not cast shadows.
- Filament as a second preview renderer: only worth it if Godot's missing sheen/IBL pieces prove too costly; adds an integration burden (inferred). bgfx: no research done.

### Gaps
- Not verified: whether Godot 4.3 Forward+ shaders can sample a sheen LUT texture in light() with IBL (probably yes via uniforms, but not checked); Godot 4.3 vs 4.4 Metal status for the user's version (the project is on 4.3, so on MoltenVK per the above, inferred).
- No located benchmarks for Godot Forward+ on M-series with SDFGI/SSR.
- bgfx not researched.

## Q3. CLO-level stills on Apple Silicon: renderer options, denoising, timings, how CLO renders

### Takeaway
CLO renders with Chaos V-Ray integrated through the V-Ray AppSDK (replacing Modo). On Apple, Cycles (Metal, with hardware RT on M3 and newer), Mitsuba 3 (Metal backend from 3.9.0, June 2026) and Octane X are the located options, and OIDN has Apple Silicon Metal support. No quantitative M3 samples-per-pixel/time numbers were located.

### Cited Findings
- Chaos blog: CLO integrated V-Ray via the V-Ray AppSDK, replacing Modo run as a separate .exe; GPU capability was a selection requirement; fabric/trim accuracy was a reason; presets mean no manual BRDF/lighting setup; plan for distributed rendering and fur. Version and denoising not stated. — [Chaos blog](https://www.chaos.com/blog/how-clo-has-integrated-v-ray-in-the-fabric-of-its-software)
- Style3D: blog says previews are rasterised and finals ray traced; it names no engine, GPU stack or denoiser; recommends RTX 30/40-series with 16GB VRAM and offers cloud rendering. Marketing-blog quality, treat with caution. — [Style3D blog](https://www.style3d.com/blog/?p=6228)
- Cycles M3 hardware RT: PR "Cycles: Apple M3 tuning including hardware raytracing" makes MetalRT the automatic default for intersection testing on M3 and later, claims "significant path-tracing speedups" and faster BVH builds, no numbers. — [Blender PR 114296](https://projects.blender.org/blender/blender/pulls/114296). A follow-up PR is titled "Properly default to Metal-RT off unless GPU is a M3 or newer". — [PR 120299](https://projects.blender.org/blender/blender/pulls/120299)
- OIDN: Metal device support for Apple Silicon GPUs arrived in the 2.2 release candidate; also ARM64 extensions. — [Phoronix](https://www.phoronix.com/news/Intel-OIDn-Metal-More-ARM64). Blender Cycles Metal OIDN support PR located (not read). — [PR 116124](https://projects.blender.org/blender/blender/pulls/116124)
- OctaneRender 2025.2 bundles OIDN 2.3.3; Octane X (macOS) supports OIDN on Metal devices, requires macOS 14.5+ on M1 or newer; 2025.4 adds macOS Tahoe support; rental-only (Studio+) with a free Prime edition limited to one GPU. — [CG Channel](https://www.cgchannel.com/?p=168023)
- Mitsuba 3.9.0 (26 Jun 2026) ships `metal_*` and `metal_ad_*` variants for Apple Silicon GPUs with Dr.Jit JIT and hardware-accelerated ray tracing; 3.9.1 (7 Aug 2026) fixes a parallel scene-loading race. — [Mitsuba release notes](https://mitsuba.readthedocs.io/en/v3.9.1/release_notes.html). Dr.Jit 1.4.0 (25 Jun 2026) introduced the Metal backend (AD, hardware RT and textures, cooperative vectors); multi-threaded use needs dr.flush_thread(); 1.6.0 (unreleased) adds Metal custom intersection functions, lower launch overhead. — [Dr.Jit changelog](https://drjit.readthedocs.io/en/latest/changelog.html)
- Metal ray tracing API background: WWDC22 session 10105 "Maximize your Metal ray tracing performance" and AppleInsider's explainer on M3 ray tracing/dynamic caching located but not read. — [WWDC22 10105](https://developer.apple.com/videos/play/wwdc2022/10105); [AppleInsider](https://appleinsider.com/articles/23/11/10/what-apples-three-gpu-enhancements-in-a17-pro-and-m3-actually-do)
- Microcylinder CPU path-traced reference: 512x512 at 144 spp took about 51 min on a 2013-era CPU (see Q1) — [PDF](https://datarepo.eng.ucsd.edu/visiondata/obisker/public_html/cloth/microcylinder-sg13.pdf)

### Inferences
- Rank for offline stills on Apple: (1) Blender Cycles driven headlessly, Metal-RT on M3+, OIDN denoise; effort M, mature, Cycles licence GPL-3 (not verified here; Blender is GPL, Cycles itself Apache-2.0 as a standalone library, to be confirmed). (2) Mitsuba 3 Metal: research-grade, good for plugging in custom cloth BSDFs and differentiable fitting, Metal backend only about four months old at this date, so high risk; BSD-3 (not verified). Effort M-L. (3) Octane X: commercial, closed, so no pipeline control. (4) Own Metal path tracer: XL, not recommended.

- Hydra Storm, RenderMan XPU and Apple-specific renderers were not located; do not rely on them.

## Q4. Digital human realism from a few selfies (brief)

### Takeaway
Selfie-to-avatar research exists (e.g., CAP4D, CVPR 2025) but is CUDA/FLAME-based and heavy; a pragmatic route for a small team is a parametric base body (MakeHuman/MPFB2 assets, CC0) with stylised-but-clean shading, because uncanny risk grows with partial photorealism.

### Cited Findings
- MakeHuman community: system assets and skin materials 01-03 are shared under CC0; eye material 03 is CC-BY; page does not mention SSS. — [MakeHuman asset packs](https://static.makehumancommunity.org/assets/assetpacks/index.html). MPFB2 is a Blender add-on listed on the Blender extensions site (licence not read). — [Blender extensions](https://extensions.blender.org/add-ons/mpfb/); [CG Channel](https://www.cgchannel.com/2025/03/check-out-open-source-blender-character-generation-plugin-mpfb-2)
- CAP4D (CVPR 2025 Oral): turns any number of reference images into an animatable avatar; needs FLAME tracking (FLAME account/licence), PyTorch3D with CUDA, hours of runtime, ideally over 64 GB RAM; licence type not visible on the page. — [GitHub](https://github.com/felixtaubner/cap4d/)
- FLAME ecosystem catalogue: — [FLAME Universe](https://github.com/TimoBolkart/FLAME-Universe)

### Inferences
- Basics to implement (unsourced, standard practice): screen-space or pre-integrated SSS for skin (Godot has SSS_STRENGTH/transmittance fields per its docs), pore-scale normal/roughness detail from a tileable map, a separate eye shader (cornea refraction/parallax iris, wet specular layer), soft studio lighting (HDRI + large area lights), plus a stylised look (flatter albedo, no photoreal hair/eyes) to dodge uncanny valley. These are inferences; no sources located.
- Effort: stylised MPFB-based avatar S-M; photoreal selfie avatar on Apple Silicon XL (CUDA dependency).

### Gaps
- No sources located on uncanny valley mitigation, skin SSS techniques for Godot, eye shading, MetaHuman licensing or Apple-compatible selfie-to-avatar pipelines.
- MPFB2 and FLAME licence terms not confirmed.
