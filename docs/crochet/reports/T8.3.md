# T8.3 — Lego overrides (§9.2)

Right-click a selection in the chart and the menu adds `#! override` lines to the end of the pattern text; the pattern recompiles and
the change shows in the chart, the summary (hinge modifiers) and the simulation. The text stays the single source of truth; Ctrl+Z in
the editor undoes an edit (one complex operation per edit).

## The text form (changed from the plan)

§9.2 sketched `override body.row(12) sts 3-7 blo` in the `.fcro` DSL. Since T4.0 patterns are CrochetPARADE text plus `#!` extension
lines, so the override is one of those (parsed in `parse.cpp` with `link` and `count`, documented in `pattern.hpp`):

```
#! override [12] blo          the whole row (row id as in `#! count`)
#! override [12,3-7] dc       stitches 3..7 of the row (index as in `#! link [row,pos]`)
#! override [6,5] flo         one stitch
```

Modifiers: a loop (`both blo flo fpost bpost space`, written worker-relative like the pattern, so BLO on a WS row is FLO on the RS) or
a type (`sc hdc dc tr slst`). Lines apply in order, the last wins. Only type and insertion change: stitches, targets, rows and counts
stay, so counts and links remain valid and no override can break a `#! count`. Chains are skipped; an address that names only chains,
no stitch, a missing row, an unknown modifier, a wrong arity or a range with a > b is an error naming the line.

"Surface sl st on this row" (in the plan's menu list) is not an override: it adds stitches. Not offered.

## UI

* Chart: **right click** (not a drag) selects the stitch under it if it is not already selected and asks for the menu; **right drag**
  still pans; a **left drag** selects a rectangle of stitches (`stitches_selected`), a click still selects one.
* Menu (`PopupMenu`, `crochet_main.gd`): header ("16 stitches, row 23"), the eight modifiers, and a tick "Make the whole row like this".
  `override_lines()` gives one line per row (whole row) or one per run of neighbouring stitches; `apply_override()` appends them.
* `get_summary()` has a new `hinge_mods` (edges with their own bending).

## Evidence

* `test_crochet_parse`: override on a row, a stitch, a range (later line wins), counts/targets/addresses untouched, and the seven
  error forms with their wording.
* `test_crochet_mesh`: pouch + `#! override [12] blo`: 1380 stitches and 2204 triangles as before, 15 stitches BLO, hinge modifiers
  8 -> 22 (14 new at bendScale 0.35: row 12 is a WS row, so the BLO as written is an RS-relative FLO, 15 stitches on 14 base edges).
* `crochet_scene_check`: 70 PASS (19 new for T8.3): row 12 whole-row BLO appends exactly `#! override [12] blo\n`, recompiles with
  hinge modifiers 8 -> 22, the recompile clears the selection, undo restores the text and the 8; `[20,3-7] dc` makes those five dc in
  the chart and the yarn grows (39.77 -> 39.89 m); two runs give two lines, one stitch `[6,5]`; chains only: nothing written and a
  message; the menu (11 items, tick state kept, BLO writes the whole-row line); a right click asks for the menu, a right drag pans
  and does not; a dragged rectangle selects the 25 stitches inside it and writes one line per row (3).
* Mutations caught: chains not skipped (parse and mesh tests), range lower bound off by one (the parse test crashes on the thrown
  error), runs merging across gaps, chains not filtered in the menu code.
* Screenshot (real renderer): `docs/crochet-shots/ui/edit_menu.png`: row 23 selected, the menu open.

## Not done

* Clicking through the menu by hand in the real window was not tried; the tests call the same functions (`_on_edit_menu`) and send the
  same mouse events to the chart.
* `#! override` lines are only appended. Editing or removing one is done in the text (or with Ctrl+Z).
