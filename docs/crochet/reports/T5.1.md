## Fixture fix found on the way (scope deviation, deliberate)

The oval base of the five bags and `tube40` was exported by CrochetPARADE with the first side
targeting the foundation chain **ascending** (`1..n`) and then the end fan on chain `0`: two
consecutive stitches whose targets are `n` chain stitches apart. Mesh faces need short base
paths (§6.2), so that surface cannot be built (the 18->0 pair was a hole). Cause: CP works an
*unturned* chain row from index 0 upward (the T4.0 report noted the index shift but not the
direction). Fix: the six fixtures say `NNch,turn` and write the second side with explicit
targets (`sc@[0,1],...,sc@[0,n]`), exactly as a crocheter works it. Row/stitch ids, counts, line
numbers and every `#!` address are unchanged; only the round-1 `targets` differ. The six exports
were regenerated (`cp_export.mjs`); the five other fixtures (pouch, three circles, facing)
regenerate **byte-identical**. One existing assertion changed because the fixture changed:
`test_crochet_parse.cpp` tube40 `g.rows[0].kind == "round"` is now `== "row" && turned` (row 0 is
a turned foundation chain, like the pouch's); the comment there says why. Documented in
`docs/CROCHET_DSL.md` section 8.
